# Core v1.7.28 — общие сообщения при массовом принятии

При массовом переводе заявок в «Принята» новые уведомления одной операции группируются по фактическому Telegram chat_id. Вместо отдельного сообщения на каждую заявку чат получает общий текст с разделителями между заявками. Сохраняется действующий шаблон каждого блока, включая магазин, поставщика, товары и комментарии. Маршруты по поставщикам остаются прежними; разные чаты получают только свои заявки. Настройка не требуется.

Объединяются только новые записи очереди текущей операции. Одиночное принятие и индивидуальная повторная отправка работают как прежде. Уже принятые заявки повторно не отправляются. Большая подборка делится по границам заявок с консервативным бюджетом 3800 UTF-16 единиц HTML. Отдельная чрезмерно длинная заявка остаётся в существующем индивидуальном механизме отправки; её текст не обрезается. Шаблон кнопки берётся из первого блока (для принятия применяется общий шаблон события).

Очередь сохраняется в той же транзакции, что и статусы заявок. Для каждого заказа сохраняется запись журнала; до доставки она может иметь статус «Ожидает в общем сообщении». После отправки участники группы получают общий message_id и результат доставки. Повторные попытки выполняются для общего сообщения. Как и ранее, при неопределённом исходе сетевого запроса Telegram может получить повтор сообщения.

Обновите файлы, сохранив переменные окружения, перезапустите сервер и заново откройте MiniApp. /health: 1.7.28. Миграций схемы и новых переменных нет. Уже поставленные в очередь до обновления сообщения не объединяются.

Проверки локальные: регрессионные тесты заявок и тесты общей доставки (один чат, разные чаты, сохранение блоков, отсутствие повторного принятия, разделение длинной подборки, повторные попытки и исчерпание попыток). Внешняя отправка заменена тестовой функцией, БД SQLite. Синтаксис JS проверен. На сервере и в реальном Telegram не проверено; установка не выполнялась.
