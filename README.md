# Причал Core v1.7 — «Проверки»

## Что добавлено

- раздел **«Проверки»** перестроен в последовательность `Провести → Контроль → История → Формы`;
- проверка начинается как черновик и может быть продолжена после повторного открытия MiniApp;
- формы можно назначать всем магазинам или выбранным точкам;
- типы полей: `Да/Нет`, выбор, число, текст, комментарий, фото;
- к каждому пункту можно добавить комментарий и несколько фотографий через Telegram;
- для пункта можно сделать фото обязательным;
- нарушения определяются автоматически по правилам формы или отмечаются управляющим вручную;
- критичность нарушения: `Низкая / Средняя / Высокая / Критическая`;
- итоговый балл проверки рассчитывается по контролируемым пунктам;
- **Контроль** показывает норму проверок по каждой точке (`N из 3`) за текущую неделю и открытые нарушения;
- из нарушения можно перейти в готовый модуль **«Задачи»** с уже заполненными магазином, названием, описанием и приоритетом;
- нарушение связывается с созданной задачей;
- **История** имеет фильтры по датам, магазину, управляющему, результату и наличию нарушений;
- в карточке проверки доступны все ответы, фото, итоговый комментарий и нарушения;
- доступна повторная проверка той же точки по той же форме;
- использованная форма при редактировании версионируется: старая остаётся в истории, новая становится рабочей;
- старый конструктор чек-листов удалён из общей админки: формы теперь находятся в `Проверки → Формы`;
- роли и уведомления не менялись.

### Обновление Neon

Сбрасывать базу не нужно. При старте v1.7 Core добавляет недостающие поля к существующим таблицам проверок и создаёт таблицу:

```text
inspection_template_stores
```

История старых проверок сохраняется.

# Причал Core v1.5 — «Пересменки: сдача и контроль»

## Что добавлено

- раздел **«Пересменки»** перестроен в последовательность `Сдать → Контроль → История → Админ`;
- продавец сдаёт пересменку по своей фактической смене из блока «График работы»;
- для дневной смены показывается окно сдачи 19:30–20:10, для ночной — 07:30–08:10 следующего дня;
- формы выбираются автоматически по магазину и типу смены;
- черновик можно сохранить и продолжить позже;
- после отправки пересменка получает статус `На проверке`;
- управляющий открывает пересменку во вкладке **«Контроль»**, видит ответы, фото и подсказки Core по отклонениям;
- решения проверки: `Принята`, `Принята с замечаниями`, `Не принята`;
- замечание можно оставить к отдельному пункту или ко всей пересменке;
- `Принять с замечаниями` и `Не принять` требуют хотя бы одного замечания;
- непринятая пересменка возвращается продавцу на исправление; после повторной отправки создаётся новая ревизия;
- история решений и снимки предыдущих ревизий сохраняются;
- во вкладке **«Контроль»** показаны также ожидаемые и не сданные пересменки по графику сотрудников;
- во вкладке **«Админ»** работает конструктор форм для каждой точки и отдельно для дневной/ночной смены;
- типы полей: текст, комментарий, число, Да/Нет, выбор, фото; поддерживаются обязательность и правила отклонений;
- фото прикрепляются через Telegram к конкретному пункту формы;
- изменение уже использованной формы создаёт новую версию, поэтому старая история не ломается;
- роли и уведомления в этом блоке пока не настраиваются — матрица прав будет добавлена позднее.

### Новые статусы пересменки

```text
draft                  Черновик
review                 На проверке
accepted               Принята
accepted_with_remarks  Принята с замечаниями
rejected               Не принята
```

### Обновление Neon

Сбрасывать базу не нужно. При старте v1.5 Core добавит недостающие поля к `shift_reports` и создаст:

```text
shift_review_remarks
shift_review_events
```

# Причал Core v1.4 — «Сотрудники» + связь с графиком

## Что добавлено

- отдельная сущность `Employee`: сотрудник больше не равен Telegram-пользователю;
- новый нижний раздел **«Сотрудники»**;
- карточка сотрудника: ФИО, должность, статус, дата приёма, комментарий, Telegram ID/аккаунт, закреплённые магазины;
- сотрудника можно создать заранее без Telegram и сразу поставить в график;
- статусы сотрудника: `Работает`, `Стажёр`, `Отпуск`, `Уволен`;
- при удалении сотрудника с историей Core не удаляет данные, а переводит его в статус `Уволен`;
- график, отсутствия, ошибки и подмены работают по `employee_id`, а не по учётной записи Telegram;
- «Мой график» определяется по связке `Employee.user_id -> User.id`;
- сотрудника можно привязать к нескольким магазинам;
- существующие данные v1.3 автоматически мигрируют при старте: создаются карточки для уже зарегистрированных пользователей и сохраняются старые смены/подмены;
- сбрасывать Neon не требуется.

# Причал Core v1.2 — блок «Заявки»

## Что изменено

- новая заявка показывает только магазины и поставщиков, доступных сегодня по графику заявок;
- сервер также запрещает создать заявку поставщику вне сегодняшнего графика;
- добавлен счётчик выполнения заявок по каждому магазину (`N из M` / `Все заявки сделаны!`);
- `Пропуск` считается выполненной заявкой, `Отменена` — не закрывает счётчик;
- комментарии к отдельным товарам удалены из интерфейса; общий комментарий заявки сохранён;
- кнопка `Копировать для поставщика` копирует текст заявки в буфер, а не создаёт дубликат;
- график поставок удалён из интерфейса; остаётся только недельный график заявок;
- редактор графика заявок перенесён в `Заявки → Админ → График заявок`;
- недельный график адаптирован под ширину телефона без горизонтальной прокрутки, поставщики различаются цветом;
- в новой заявке добавлен поиск по товарам;
- кнопка `Фильтр` уменьшена и находится сразу под подменю;
- нижнее общее меню вынесено из sticky-header и закреплено внизу экрана;
- в `Админ → Товары` добавлен массовый импорт XLSX/CSV/TSV и скачиваемый CSV-шаблон;
- вкладка `Роли` сохранена как заглушка до реализации всех модулей.

### Формат массового импорта товаров

Колонки: `Товар`, `Поставщик`, `Категория`, `Единица`. Поставщик должен существовать заранее. Категории и единицы измерения при необходимости создаются автоматически. Совпадающий товар у того же поставщика обновляется.

Чистая сборка Telegram-бота + MiniApp для операционного управления сетью.

## Стек

- Python 3.11+
- FastAPI + Uvicorn
- Neon PostgreSQL через SQLAlchemy + psycopg
- Telegram Bot API
- MiniApp: HTML + CSS + vanilla JavaScript, без Node.js и package.json
- Фото физически хранятся в Telegram; в PostgreSQL сохраняются file_id и метаданные

## Что включено

- Telegram `/start`, `/whoami`, webhook
- Telegram MiniApp authorization с проверкой подписи initData
- Роли: seller, mentor, manager, operations_director, leader, admin
- Пользователь может быть привязан к нескольким магазинам
- Администратор управляет магазинами, поставщиками, категориями, товарами, расписаниями, пользователями и ролями
- Заявки поставщикам: создание продавцом, статусы и редактирование управляющим
- Редактируемые шаблоны пересменок для каждой точки
- Редактируемые чек-листы проверок
- Автоматическое создание нарушений из чек-листа
- Задачи: только руководство/ОД/управляющие создают; приоритет, срок, фото, статус
- Инкассации: сумма, кто забрал, передача в офис, подтверждение
- Наставничество/стажировки
- Ручной план/факт до интеграции с Saby
- Рейтинг магазинов: план + проверки + нарушения + задачи + пересменки
- Плановые рассылки по ролям/точкам/дням недели
- Авто-уведомления: просроченные задачи, несданные пересменки, отсутствующие заявки, недостаток проверок, низкий план
- Фото через Telegram с привязкой к пересменке/проверке/задаче
- Отдельный endpoint для будущего внешнего AI-агента


## Что изменено в v1.1 — блок «Заявки»

- глобальная кнопка «Заявки» остаётся в нижней навигации
- внутри раздела верхнее меню: `Новая → Список → График → Админ → Роли`
- фильтры списка скрыты в одну кнопку «Фильтр»
- фильтры: статус, сегодня/вчера/неделя/конкретная дата, магазин, поставщик
- статусы: `Новая`, `Принята`, `Отменена`, `Пропуск`
- карточка заявки с автором, товарами, комментариями, изменением статуса, удалением и копированием
- состав заявки можно менять, пока статус `Новая`
- создание «Пропуска» без товаров
- недельные графики заявок и поставок Пн–Вс с редактированием
- админ-раздел заявок: магазины, поставщики, товары, категории, единицы измерения, лимиты, ассортимент по точкам, прайс-листы
- лимиты количества товара проверяются при создании/редактировании заявки
- прайс-листы прикрепляются документом через Telegram, в Neon хранится `file_id` и метаданные
- вкладка «Роли» оставлена как заглушка: до настройки матрицы прав весь функционал раздела «Заявки» доступен всем активным пользователям

## 1. Файлы в GitHub

В корне репозитория должны находиться:

```text

.env.example
```

В проекте намеренно нет `package.json`, Node.js backend и Dockerfile. JavaScript MiniApp находится inline в `miniapp/index.html`, чтобы серверный runtime однозначно оставался Python.

## 2. Настройки Bothost

Создайте Python Telegram-проект из GitHub.

Рекомендуемые параметры:

```text

Порт: 5000
Ветка: main
```

### Как получить Telegram ID

После первого деплоя отправьте боту:

```text
/whoami
```

Бот вернёт ID. Добавьте его в `BOOTSTRAP_ADMIN_TELEGRAM_ID` и сделайте redeploy.

## 4. Neon

Нужна одна рабочая pooled connection string Neon в `DATABASE_URL`.

При старте Core создаёт отсутствующие таблицы автоматически через SQLAlchemy `create_all`. Это удобно на первом этапе активной разработки. Перед стабильным production-релизом рекомендуется перейти на Alembic migrations.

## 5. Первая проверка после deploy

Откройте:

```text
/health
```

Ожидается:

```json
{"status":"ok","service":"prichal-core","version":"1.1.0"}
```

Затем:

```text
/db-health
```

Ожидается `status: ok` и `probe: 1`.

После этого отправьте Telegram-боту `/start` и откройте MiniApp.

## 6. Первый запуск только для администратора

1. Укажите свой Telegram ID в `BOOTSTRAP_ADMIN_TELEGRAM_ID`.
2. Откройте MiniApp.
3. Перейдите `Админ`.
4. Создайте магазины.
5. Создайте поставщиков и сроки заявок.
6. Создайте категории и товары.
7. Настройте дни заказа поставщиков по точкам.
8. Создайте шаблоны утренних/вечерних пересменок.
9. Создайте чек-лист проверки магазина.
10. После этого приглашайте тестового продавца/управляющего.

## 7. Фото

MiniApp не загружает изображения в Neon. Пользователь нажимает `+ Фото`, Core отправляет ему сообщение в Telegram и ждёт следующую фотографию. Telegram хранит файл, Core сохраняет:

- `telegram_file_id`
- `telegram_file_unique_id`
- автора
- связанную сущность
- магазин
- дату

Это позволяет позже без миграции добавить S3-архив.

## 8. AI

AI не встроен в ядро. Это отдельный модуль. Когда существующий AI-агент будет готов, задаются:

```text
AI_AGENT_URL
AI_AGENT_SECRET
```

Core сможет передавать ему контекст, а сам AI-модуль будет развиваться независимо.

## 9. Важное про планировщик

Встроенный scheduler рассчитан на один процесс приложения. На Bothost держите один экземпляр/worker, пока фоновые уведомления выполняются внутри Core. При горизонтальном масштабировании планировщик следует вынести в отдельный worker/cron, чтобы не было дублей уведомлений.

## v1.3 — График работы

Добавлен отдельный блок `График` с подменю:

- Мой график;
- По магазинам;
- Редактор;
- Подмены;
- Ошибки;
- История.

Модель смен: дневная — 1 продавец, ночная — 2 продавца. Редактор работает помесячно и разрешает менять прошлые даты. Поддерживаются выходной, отпуск, больничный и обучение. Система блокирует назначение сотрудника на несколько смен/точек в один день, назначение на незакреплённую точку и дневную смену сразу после ночной. Раздел `Ошибки` контролирует недоукомплектованные смены и конфликты, а `Подмены` позволяет подобрать свободного сотрудника по фактическому графику.

В этой версии права на новый блок намеренно не ограничены по ролям — редактор ролей будет подключён после реализации остальных функциональных блоков. Уведомления также пока не включены.

### Новые таблицы PostgreSQL

`work_shift_assignments`, `work_absences`, `work_schedule_changes`, `work_substitutions`.

При обновлении с v1.2 сбрасывать Neon не нужно: таблицы создаются автоматически при старте приложения.

## v1.6 — Задачи

Новая версия блока «Задачи» переведена на расширенную модель `tasks_v2`.

Поддерживается:
- назначение одному или нескольким сотрудникам;
- назначение целому магазину (исполнителями становятся все активные сотрудники магазина);
- задачи без магазина;
- статусы: Новая → В работе → На проверке → Выполнена / Не принята / Отменена;
- финальное принятие результата постановщиком/руководством;
- обязательное замечание при возврате задачи;
- приоритеты: низкий, обычный, высокий, срочный;
- срок с датой и временем;
- ежедневная / еженедельная / ежемесячная повторяемость;
- чек-листы и прогресс отдельно для каждого исполнителя;
- фото к задаче и к пунктам чек-листа через Telegram;
- файлы через Telegram;
- комментарии внутри задачи;
- фильтры контроля по статусу, приоритету, магазину, сотруднику, постановщику и сроку;
- полная лента истории действий;
- редактирование основных параметров задачи с фиксацией изменений.

Роли и автоматические уведомления в этой версии намеренно не расширялись — они будут настраиваться позже в общем редакторе ролей и уведомлений.
