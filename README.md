# Причал Core v1.7.10 — Security & Permissions Stabilization

v1.7.10 построена поверх рабочей v1.7.9. Новых бизнес-модулей в этой версии нет: основная задача — сделать новую матрицу ролей реальным серверным механизмом доступа, а не только настройкой интерфейса.

## Что изменено

- `users.role_key` — основной источник роли и разрешений.
- Права проверяются на backend по модели:
  - `hidden` — действие недоступно;
  - `view` — только просмотр;
  - `edit` — просмотр и изменение.
- Для разрешений учитывается область данных:
  - `own` — только собственные данные;
  - `stores` — закреплённые магазины;
  - `network` — вся сеть.
- Кастомная роль больше не получает дополнительные права через старое поле `users.role` / `base_role`.
- Только системная роль `admin` является неизменяемым superuser.
- Прямые API-запросы проверяют матрицу прав независимо от того, скрыта кнопка в MiniApp или нет.
- Отключённые модули защищены на сервере: прямой вызов возвращает HTTP 404.

## Модули, переведённые на единый слой доступа

- Заявки и их справочники;
- График работы и подмены;
- Пересменки;
- Задачи;
- Проверки;
- Сотрудники;
- База знаний;
- Тестирование;
- Telegram-группы / маршруты / доставка;
- Главная и виджеты.

Фото и вложения также проверяют право доступа к связанному объекту.

## Отключённые модули

Пока выключены через `module_states`:

- Инкассация;
- Наставничество;
- План/факт;
- старый Рейтинг;
- старые Рассылки.

Код и данные не удаляются. После будущего включения модуль можно вернуть без восстановления из архива.

## Проверки перед сборкой

Перед упаковкой v1.7.10 выполнены:

- Python compilation — OK;
- JavaScript syntax — OK;
- SQLite DB smoke-test — OK;
- 74 таблицы создаются — OK;
- Security regression test — OK.

Security regression проверяет в том числе:

- кастомная роль не наследует legacy-права;
- scope не выдаёт чужие магазины;
- скрытое действие нельзя вызвать напрямую через API;
- выключенный модуль нельзя открыть прямым URL;
- системный admin сохраняет полный доступ;
- копия роли Администратора не становится вторым superuser.

Подробности: `SECURITY.md`.

## Обновление

Neon очищать не нужно. v1.7.10 не требует сброса существующих данных.

После deploy проверьте:

```text
/health
```

Ожидаемая версия:

```json
{
  "status": "ok",
  "service": "prichal-core",
  "version": "1.7.10"
}
```

После запуска рекомендуется открыть `Админ → Роли` и проверить реальные права каждой рабочей роли перед подключением AI, Bitrix и Saby.
