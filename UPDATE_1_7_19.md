# Причал Core v1.7.19 — заявки, товары, сотрудники, оформление

Исходная версия: загруженный пользователем архив v1.7.18; его содержимое сверено с рабочими исходниками. Установка на рабочий сервер не выполнялась.

## Изменения

- Один магазин может создать только одну заявку поставщику за местный календарный день. В PostgreSQL параллельные создания сериализуются блокировкой строки магазина. Любой существующий статус, включая отмену, занимает лимит; удаление освобождает его. Исторические дубликаты не удаляются.
- Без товаров и без отметки «Пропуск» непустой комментарий создаёт статус «Только комментарий». Он закрывает обязательство магазина. Добавление товаров переводит заявку в «Новую»; удаление всех товаров при сохранённом комментарии — обратно. Пустая заявка запрещена.
- Нижний счётчик учитывает только «Новые» и «Только комментарий». После операций счётчик пересчитывается, а не обнуляется.
- Время API передаётся с UTC-смещением; заявки в MiniApp показываются по Екатеринбургу. В Telegram применяется APP_TIMEZONE. Для этой сети используйте APP_TIMEZONE=Asia/Yekaterinburg.
- Статусы: новая — синий, комментарий — фиолетовый, принятая — зелёный, пропуск — янтарный, отменённая — красный.
- Массовый выбор: принять, отменить, вернуть в новые, удалить; до 100 заявок за операцию. Проверяются права и область доступа для каждой заявки. Ошибка проверки откатывает всю операцию. Принятие и постановка отправок в очередь выполняются в одной транзакции. Каждая заявка маршрутизируется отдельно. Повторное принятие уже принятой заявки не дублирует отправку.
- Автор заявки берётся из карточки сотрудника. Если связанной карточки нет, показано «Сотрудник не привязан».
- Список/плитка товаров переключается без потери введённых количеств; выбор вида сохраняется на устройстве.
- Просроченное невыполненное обязательство подсвечивает счётчик красным. Планировщик использует действующий график заявок и местные границы суток. Новый шаблон «Не подана заявка» доступен в редакторе Telegram-шаблонов.
- Уведомления направляются действующим управляющим, закреплённым за магазином в «Сотрудниках» и связанным с активными Telegram-аккаунтами. Одно уведомление за день/магазин/поставщика/получателя, в том числе при повторном проходе планировщика. После перезапуска проверяются уже наступившие сроки текущего дня. Исправлено обращение планировщика к отсутствовавшему полю журнала уведомлений.
- Редактор товара: название, единица, индивидуальный положительный шаг, категория, поставщик для ручных товаров. Активность меняется существующей кнопкой списка; лимиты магазинов — во вкладке «Лимиты». Поставщик импортированных товаров меняется для всего прайса в «Прайсы Saby».
- Название и единицу импортированного товара можно исправить вручную. Импорт сохраняет правки и ручное отключение. Кнопки возврата из Saby используют последнее успешно загруженное исходное значение. Изменение исходной единицы требует подтверждения шага даже при ручной единице. Изображения продолжают обновляться существующим механизмом S3/ETag.
- Сотрудники: фильтр по магазинам, фото слева, просмотр личной страницы с вкладками «Профиль», «Работа», «Обучение», «Активность». Контакты доступны по отдельному праву. Настройки чужого профиля не показываются.
- Добавлены темы «Лес», «Роза», «Полночь». Кнопки, уведомления и элементы Telegram получают цвета выбранной темы. Цвета ошибок и статусов сохраняют смысл.

## Настройка после обновления

1. Сохранить резервную копию базы и текущей версии. Заменить исходники содержимым архива штатным способом Bothost и перезапустить приложение. Миграция добавляет три поля к импортированным товарам, сохраняет товары, шаги и историю; выполняется один раз. Новые ключи и переменные окружения не требуются.
2. Проверить `/health`: версия должна быть `1.7.19`. Закрыть MiniApp полностью и открыть снова: имена статических файлов изменены для сброса старого кэша.
3. Администратор получает массовые действия автоматически. Для других ролей включить «Заявки → Массовые действия с заявками» с уровнем редактирования и нужной областью данных. Дополнительно нужны права конкретных действий: принятие, отмена, редактирование, удаление.
4. Для просмотра личных страниц включить «Сотрудники → Личные страницы других сотрудников». Для показа кнопки и фотографий нужен доступ к списку сотрудников. Для телефона и почты отдельно настроить «Контактные данные» и область доступа.
5. Проверить активные Telegram-маршруты поставщиков. Если маршрут не настроен, заявка принимается, но отправка невозможна; массовое действие сообщает об этом. После настройки доступна существующая повторная отправка.
6. Для автоматических уведомлений: `ENABLE_SCHEDULER=true`, `APP_TIMEZONE=Asia/Yekaterinburg`; у управляющих — должность «Управляющий», магазины и связанный активный аккаунт. Отредактировать шаблон «Не подана заявка» при необходимости.
7. В редакторе товара после изменения единицы проверить шаг и сохранить. Возврат из Saby отменяет ручную правку соответствующего поля. Для получения новых значений источника сначала обновить прайс.

## Проверки

Автоматически, локально:
- 89 существующих серверных тестов прошли при общей проверке. Единственный устаревший тест пытался создать вторую заявку за день для проверки дробного количества; он изменён на редактирование первой заявки, чтобы сохранить проверку кратности.
- Затем прошли 13 целевых серверных тестов: исправленный тест и 12 новых, включая миграцию старой схемы, повторный запуск миграции, комментарии, ежедневный лимит, удаление, отмену, границы суток, счётчики, дробные шаги, маршруты массового принятия, отказ по правам, сохранение ручных значений, возврат Saby, изменение единицы, фильтр магазинов, личные страницы, темы, однократные уведомления и отсутствие уведомления при выполненном обязательстве.
- 26 JavaScript-тестов прошли, в том числе навигация/кэш, сохранение количества при смене вида, отображение времени, редактор товара и просмотр чужого профиля.
- Синтаксис Python и JavaScript проверен.

Тесты используют SQLite, тестовое S3 и очередь сообщений без реальной отправки. Проверок на рабочем сервере не проводилось.

После установки проверить вручную: одновременное создание с двух телефонов на PostgreSQL (одна успешная заявка, второй получает отказ); миграцию на серверной базе; получение управляющими уведомлений; массовое принятие в реальные чаты; новые темы, плитку и миниатюры в мобильном Telegram. Полноценная визуальная проверка в мобильном браузере здесь не выполнена.
