# Core v1.7.17 — одобрение доступа Telegram-аккаунтов

Исправлен незавершённый сценарий регистрации: связь аккаунта с сотрудником сама по себе не снимала pending, а в новом админ-центре не было действия одобрения.

## Если сотрудник уже создан

1. Обновите Core этой полной сборкой, сохранив существующие настройки сервера.
2. Проверьте `/health`: версия должна быть `1.7.17`.
3. Админ-центр → Пользователи → найдите Telegram ID.
4. Выберите роль и нажмите **Одобрить доступ**. Статус станет active.
5. Попросите человека закрыть и заново открыть MiniApp Core.

Повторно создавать карточку сотрудника не нужно. Альтернативный путь: открыть существующую карточку, выбрать роль доступа и нажать **Сохранить и предоставить доступ**.

## При создании сотрудника

Заполните ФИО, должность, кадровый статус и магазины. Выберите зарегистрированный аккаунт в поле «Связанный Telegram-аккаунт». В блоке «Доступ в Core» явно выберите роль и нажмите **Сохранить и предоставить доступ**.

Должность и роль доступа выбираются отдельно. Обычная кнопка «Сохранить» / «Создать» сохраняет только карточку. Простого ввода Telegram ID для одобрения недостаточно: нужно выбрать аккаунт из списка.

## Ограничения и проверки

Одобрение разрешено только администратору на сервере, независимо от видимости кнопки. Операция принимает только ожидающий активный аккаунт pending. Она не разблокирует отключённые аккаунты и не выдаёт доступ уволенному или неактивному связанному сотруднику. Повторное одобрение уже активного аккаунта с той же ролью безопасно; смена роли проводится отдельным существующим действием.

Сохранение сотрудника, привязки, магазинов и одобрение выполняются в одной транзакции: при ошибке изменения откатываются. Одобрение записывается в журнал администратора. Автоматически одобрять всех ожидающих пользователей сборка не будет.

Новых миграций относительно v1.7.16 нет. Импорт прайсов, фото и прочие функции включены в сборку. Если устанавливаете поверх более ранней версии, также прочитайте RELEASE_1.7.16.md.

Автоматически проверены: снятие pending и доступ к /api/auth/me, запрет неадминистратору, создание и одобрение в одной операции, одобрение существующей карточки, отсутствие одобрения при обычном сохранении, откат при ошибке роли/магазина/кадрового статуса, защита отключённых аккаунтов, повторный запрос, выбор роли через интерфейс. Тесты используют локальную SQLite и имитацию браузера jsdom.

На сервер сборка не устанавливалась; вход реального пользователя через Telegram после обновления нужно подтвердить на сервере.
