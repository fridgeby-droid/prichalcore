# Причал Core 1.7.13 — кэш данных Mini App

Полная сборка включает все изменения 1.7.12: прямые фото в S3, миниатюры, оптимизацию SQL, миграции и фоновые очереди. Описание и порядок развёртывания: RELEASE_1.7.12.md.

## Кэширование

Кэш JSON находится только в памяти открытого Mini App. Он не записывает персональные данные в localStorage, sessionStorage или общий серверный кэш. Redis и новые переменные окружения не нужны.

| Данные | Свежий кэш | Предельный возраст |
|---|---:|---:|
| Магазины /api/reference/stores; единицы, категории, поставщики заявок | 5 минут | 10 минут |
| Главная, счётчики, личная страница, списки задач, контроль и история пересменок/проверок, база знаний | 15 секунд | 30 секунд |

Пока кэш свежий, повторное обращение не делает HTTP-запрос. После первого срока сохранённые данные показываются сразу, а сервер опрашивается в фоне. Если они изменились, появляется кнопка «Обновить». После предельного срока экран ждёт свежий ответ; просроченные данные при ошибке сети не выдаются за актуальные. Это кэш ответов API, а не снимков HTML и не офлайн-режим.

Фоновое обновление не перерисовывает формы и не уничтожает введённый текст. Счётчики меню обновляются автоматически. В верхней панели добавлена кнопка принудительного обновления; при наличии полей ввода она спрашивает перед перезагрузкой экрана. После возвращения из фона через 30 секунд кэш сбрасывается и предлагается обновить экран.

## Сброс и защита

- Любая операция записи сбрасывает кэш до и после запроса, в том числе при сетевой ошибке. Загрузка фото дополнительно сбрасывает его после завершения фоновой обработки.
- Одинаковые одновременные GET объединяются; разные фильтры и страницы имеют разные ключи. Каждый потребитель получает отдельную копию данных.
- Смена токена очищает кэш. Ответ старого запроса после смены пользователя или записи не возвращается в экран и не наполняет кэш заново.
- При 401/403 кэш очищается и показывается сообщение об изменении доступа. Уже показанные данные могут оставаться видимыми до очередной проверки; мгновенного межклиентского отзыва без обращения к серверу нет.
- Авторизация, активные тесты, статусы загрузки медиа, детали задач и прочие не включённые явно маршруты не кэшируются. Серверные проверки прав и состояния при записи сохранены.
- Лимит: 100 ответов и 4 МиБ оценочного объёма JSON (без учёта служебных расходов JavaScript). Старые записи вытесняются. Кэш фото из 1.7.12 действует отдельно.
- API получает заголовок private, no-store, чтобы браузерный HTTP-кэш не подменял управляемый кэш Mini App. Статические файлы получили новые имена.

Изменения другого сотрудника становятся видны при следующей загрузке/проверке, согласно указанным срокам. Постоянно открытый экран сам по таймеру не перезагружается; кнопка обновления запрашивает актуальные данные сразу.

## Проверено

- 13 сценариев кэша: TTL, фоновая проверка, повторные и параллельные запросы, изоляция пользователей, гонка GET/запись, ошибки, обход кэша для критичных маршрутов, ограничения памяти.
- 21 серверная проверка предыдущей версии повторно прошла.
- DOM-сценарий прямой загрузки фото прошёл с подключённым кэшем; S3 и обработка изображения в браузере заменены заглушками.
- Синтаксис JavaScript и Python проверен.

Команда проверки кэша: `node --test tests/cache.test.cjs` (Node нужен только для этих тестов, не для сервера).

Реальное время загрузки на устройстве и Telegram WebView здесь не измерялось. Развёртывание, рабочий PostgreSQL и Timeweb S3 не использовались. Обновление не добавляет миграций относительно 1.7.12; при переходе с 1.7.11.8 выполняются миграции, описанные в предыдущем выпуске.
