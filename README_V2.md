# Причал — фундамент v2

Это переходная версия существующего бота заявок. Внешний интерфейс MiniApp и старые API сохранены. Цель версии — подготовить проект к пересменкам, проверкам, задачам, инкассациям и будущей интеграции с AI-агентом.

## Что изменено

1. Секреты вынесены из `app.py` в переменные окружения (`config.py`).
2. Telegram MiniApp `initData` теперь проверяется криптографически (HMAC) перед определением пользователя/администратора.
3. Добавлен стабильный числовой `store_id`, при этом старое поле `shop` остаётся для совместимости.
4. Добавлен реестр пользователей `users_v2.json` (создаётся миграцией; пока роли не ограничивают старый функционал).
5. Новые заявки сразу получают `store_id`.
6. Запись JSON сделана атомарной, чтобы снизить риск повреждения файла при записи.
7. Повреждённый JSON больше не перезаписывается молча пустыми данными.
8. Добавлены совместимые v2 endpoints: `/api/v2/me` и `/api/v2/stores`.
9. Добавлен идемпотентный скрипт `scripts/bootstrap_v2.py`, который создаёт каталог точек, реестр пользователей и добавляет `store_id` в исторические заявки с резервной копией.

## ВАЖНО перед загрузкой на рабочий сервер

Не заменяйте рабочие `orders.json`, `shops.json`, `schedule.json`, `products.json`, `suppliers.json`, `admins.json` файлами из тестового архива. На сервере могут уже быть более свежие данные.

Загрузите поверх рабочего проекта только кодовые файлы из patch-архива, затем выполните миграцию на серверной копии данных.

## Переменные окружения Bothost

Нужно создать:

- `BOT_TOKEN` — новый токен Telegram-бота;
- `APP_URL=https://prichal59.bothost.tech`;
- `GROUP_CHAT_ID=-1002451968808`;
- `DAILY_NOTIFICATION_SECRET` — новый длинный случайный секрет;
- `PERM_OFFSET=5`;
- `TELEGRAM_AUTH_MAX_AGE_SECONDS=86400`.

Токен, который ранее находился прямо в `app.py`, рекомендуется перевыпустить через BotFather и старый токен больше не использовать.

## Миграция текущих данных

После загрузки кода на сервер выполнить из корня приложения:

```bash
python scripts/bootstrap_v2.py
```

Скрипт:

- не удаляет заявки;
- перед изменением создаёт резервную копию `orders.json` в `backup/`;
- добавляет `store_id` к существующим заявкам;
- создаёт `store_catalog.json`;
- создаёт `users_v2.json` на основе истории заявок и `admins.json`;
- допускает повторный запуск.

## Проверка

После перезапуска:

1. `/health` должен отвечать `status: ok`.
2. Открыть MiniApp из Telegram и создать тестовую заявку.
3. Проверить, что заявка появилась как раньше.
4. В `orders.json` у новой заявки должно быть одновременно `shop` и `store_id`.
5. Проверить админскую часть из Telegram — права должны работать как прежде.
6. После смены токена открыть `/setwebhook`, чтобы заново зарегистрировать webhook.
