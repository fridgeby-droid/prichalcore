# Причал Core v1.7.16 — прайсы Saby через Причал AI

Основа: подготовленная сборка Core v1.7.15. Версия работающего сервера не подтверждалась. Контракт: AI v0.3.18, `CORE-PRICE-LISTS-API.md`, копия включена в `docs/`.

## Возможности

В «Админ-центр → Прайсы Saby» администратор получает список прайсов для точки Saby, выбирает прайс и поставщика Core. Подключение запускает фоновую загрузку. Кнопка «Обновить статусы» показывает результат; ожидание загрузки не блокирует работу в других разделах.

В «Товары и шаги» каждый товар получает отдельный положительный шаг (например 0.5 кг, 1 упаковка, 6 шт). Общего шага нет. Новый товар скрыт в заявках до подтверждения шага. При изменении единицы подтверждение сбрасывается, даже если единица позже вернулась к прежней. Само введённое значение шага сохраняется для повторного подтверждения.

Импорт получает названия, единицы, изображения. Цены и остатки не используются. Сопоставление учитывает подключение, настроенный адрес AI, ID точки, прайса и товара. Одинаковые названия допустимы. Поставщик и шаги сохраняются при повторной загрузке. Старые ручные товары автоматически по названию не объединяются с импортированными: при необходимости отключите прежние дубли отдельно.

Открытие заявки читает только локальную БД; AI и Saby не вызываются. Названия и единицы фиксируются в строках заявки, включая заполнение снимков для прежних заявок при миграции. Количества передаются строками, проверяются Decimal на сервере, хранятся в PostgreSQL NUMERIC(18,6): до 12 целых и 6 дробных цифр. Количество должно быть положительным и кратным индивидуальному шагу. Ограничения магазина и расписание поставщика продолжают действовать.

## Настройка сервера Core

Сохраните резервную копию БД перед обновлением. Загрузите полную сборку, сохранив действующие переменные окружения, настройки PostgreSQL и S3. В параметрах сервера задайте:

```dotenv
CORE_PRICE_LISTS_AI_URL=https://prichal-ai.bothost.tech
CORE_PRICE_LISTS_SOURCE_ID=prichal-ai
CORE_PRICE_LISTS_API_KEY=<тот же отдельный ключ, что задан на AI>
```

Ключ вводится только в настройках серверов, не в интерфейсе Core и не в чате; минимум 32 символа. `CORE_DIRECTORY_API_KEY`, `PRICHAL_AI_URL` для существующей интеграции и `/api/v1/core/directories` менять не требуется. Для прайсов рекомендуется явно задать `CORE_PRICE_LISTS_AI_URL`. Если он пуст, используются PRICHAL_AI_URL, затем AI_AGENT_URL, затем указанный адрес AI по умолчанию.

Нужны действующие `S3_ENDPOINT_URL`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_PREFIX` Core. Публичный доступ к бакету не нужен. Фотографии скачиваются сервером, сохраняются под префиксом Core и выдаются после авторизации. AI-ключ и подписанные download_path не передаются браузеру.

Перезапустите приложение. Миграция `price-lists-1.7.16` выполняется автоматически: три таблицы импорта, поля снимков строк заявки, расширение точности количества, снятие уникальности товара по имени поставщика. PostgreSQL использует блокировку миграции; миграция повторяемая. Проверяйте `/health`: ожидаемая версия `1.7.16`. Это необходимое подтверждение установки, а не факт, установленный при подготовке архива.

Для отката после начала работы с новыми прайсами используйте согласованную резервную копию БД и прежнюю сборку: старый код не обеспечивает новые правила шагов.

## Проверка связи Core → AI

В консоли контейнера Core, где уже заданы переменные окружения:

```bash
python scripts/check_price_ai.py --point 23109 --price 66 --image
```

Команда проверяет защищённые HTTP-запросы списка, состава и одного изображения, его хеш и создание миниатюры. Она не пишет ассортимент в БД или S3 и не выводит ключ либо download_path. Успех: `ok: true`, `complete_snapshot: true`; по ранее подтверждённым пользователем данным ожидаются 47 товаров и 2 исключённых раздела. Текущий ассортимент Saby может измениться.

HTTP-клиент Core ждёт чтение ответа прайса до 310 секунд, больше 240 секунд AI. Внешний прокси также должен разрешать длительный запрос получения списка прайсов. Сам импорт состава выполняется фоновым работником Core и не удерживает запрос браузера.

## Приёмка через интерфейс

1. Админ-центр → Прайсы Saby → точка `23109` → Получить список прайсов. Выберите «ДОСТАВКА», ID `66`, и существующего поставщика Core.
2. Подключите прайс, затем обновите статус. Загрузка закончена при «Обновлён»; ошибки фото показываются отдельно, товары при этом уже могут быть импортированы.
3. Откройте товары, проверьте наименования, единицы и миниатюры. В таблице отображается первое доступное фото; сервер сохраняет все переданные изображения. Без фото отображается заглушка.
4. Подтвердите разные шаги нескольким товарам. До этого они недоступны в заявках. Создайте заявку для магазина, которому поставщик доступен по расписанию; при настроенном ассортименте магазина включите новые товары в него.
5. Для шага 0.5 проверьте количество 1.5, затем ручное 1.6: второе должно быть отклонено сервером.
6. Повторите импорт: ID товаров, поставщик и шаги сохраняются. Измените единицу в Saby — после импорта товар должен ждать подтверждения шага.
7. Удаление товара из полного снимка отключает его для новых заявок. Уже созданная заявка сохраняет прежние название и единицу. Ошибка AI не должна менять доступность ассортимента.
8. Замените фото при прежнем адресе в Saby и повторите импорт. Core делает условную проверку ETag на каждой синхронизации, даже при прежней revision. При 304 оригинал не скачивается и в S3 не записывается повторно. После изменения файла создаётся новый объект и миниатюра. Кэш миниатюр браузера — до 60 секунд.

Автоматическое обновление включается отдельно для каждого прайса, интервал 30 минут после завершения. Ошибки API повторяются с задержкой до 60 минут (до пяти повторов при выключенном автообновлении). Ошибки изображений повторяются через 5 минут. База хранит очередь; после аварийного завершения задача может ждать истечения аренды до 10 минут. Работник прайсов отдельный от работника фото/сообщений.

## Защита данных при обновлении

Снимок применяется транзакционно только после HTTP 200, проверки схемы v1, ожидаемых идентификаторов, количества товаров и `complete_snapshot: true`. Подтверждённый пустой снимок отключает товары. Частичный ответ, неправильные ID, тайм-ауты и ошибки HTTP ассортимент не очищают.

PostgreSQL блокирует запись прайса, задаче выдаётся новый токен; старый работник не может применить результат после смены токена. Дополнительно отклоняется fetched_at старше сохранённого. Настройка шага и запись заявки используют согласованный порядок блокировок с импортом.

Изображения проверяются по относительному доверенному пути, без переходов по редиректам, с ограничением 10 МиБ и проверкой SHA-256/ETag. Сбой фото или S3 сохраняет прежнее фото. Если источник явно возвращает images=[], фото скрывается. Старые объекты сохраняются; автоматическая очистка не входит в эту сборку.

## Что проверено

Автоматически локально: 82 Python-теста и 21 JavaScript-тест. Проверены повторный импорт, стабильные ID и одинаковые имена, сохранение поставщика/шагов, новые и исчезнувшие товары, смена единицы, точные дробные количества, снимки истории, ошибки и неполные ответы, устаревшие задачи, ETag/304, изменённые байты по прежнему адресу, сбои S3, безопасные пути фото, права администратора, интерфейс шагов и кнопки количества. Существующие тесты фото, справочников, кэша и переходов также проходят. Проверена повторяемость миграции прежней схемы на SQLite.

Фактически на сервере в этой работе **ничего не устанавливалось и не проверялось**. Полный прайс 23109/66 (47 товаров, 2 раздела исключены) и скачивание одной фотографии на AI подтверждены пользователем ранее. Это не подтверждает HTTP-связь из Core.

Осталось проверить на сервере: защищённый Core → AI, реальные права S3, миграцию на копии PostgreSQL/Neon, параллельную работу нескольких процессов PostgreSQL, интерфейс в Telegram на телефоне и фактическую версию после установки. Локальные интеграционные тесты используют SQLite и имитацию AI/S3; они не заменяют эти проверки. Для производственных количеств и блокировок предусмотрен PostgreSQL.
