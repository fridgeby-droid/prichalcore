# Core v1.7.32 — исправление миграции вложений

Причина: в v1.7.30–31 модель order_attachments была добавлена, но отдельная
миграция для ранее установленной базы отсутствовала. Полное create_all
запускается только при первоначальной установке. Поэтому тесты на новой
базе проходили, а существующая PostgreSQL возвращала UndefinedTable.

## Исправление

- При запуске добавлена версионированная миграция order-attachments-1.7.32.
- Она создаёт таблицу с индексом и внешними ключами, если таблицы нет.
- Существующая таблица и данные сохраняются. Повторный запуск безопасен.
- В PostgreSQL создание таблицы и запись версии выполняются в одной
  транзакции под существующей advisory-блокировкой миграций.
- При ошибке миграции запуск прерывается; версия не отмечается выполненной.
  Перед освобождением PostgreSQL-блокировки откатывается незавершённая транзакция.
- Массовое редактирование товаров и остальные функции v1.7.31 сохранены.
  Файлы интерфейса остаются версии 1.7.31: интерфейс не менялся.

## Установка и проверка

1. Сделать обычную резервную копию базы перед обновлением.
2. Загрузить эту сборку вместо предыдущей и перезапустить приложение.
   Переменные окружения и подключение к существующей базе оставить прежними.
3. Проверить /health: версия приложения должна быть 1.7.32.
4. Убедиться, что приложение успешно запустилось без ошибки миграции.
5. Открыть прежнюю заявку (например №170), проверить загрузку списка вложений.
6. На редактируемой заявке прикрепить Excel, скачать его, затем проверить
   отправку поставщику на согласованной тестовой заявке/группе.

Не нужно удалять базу, заявки или таблицу core_schema_versions.
Если миграция завершается ошибкой доступа, нужны права CREATE в рабочей схеме
для пользователя приложения; прислать полный лог запуска без секретов.

## Проверки

Автоматически локально на SQLite: обновление базы со старыми маркерами и
отсутствующей таблицей; сохранение прежней заявки; индекс; загрузка и скачивание
Excel после миграции; повторный запуск; таблица без маркера; ошибка DDL без
записи версии и успешная повторная попытка. Дополнительно тесты вложений,
отправки с повторными попытками и массового изменения товаров (S3/Telegram
заменены тестовыми реализациями).

На сервере ничего не устанавливалось. Реальная PostgreSQL, S3 и отправка
в Telegram требуют проверки после установки. Создание таблицы не исправляет
возможные отдельные ошибки конфигурации S3 или прав Telegram.
