# Причал Core 1.7.15 — справочники Причал AI и связи с Saby

Полная сборка включает быстрые переходы, кэш, прямые фото S3 и все изменения 1.7.14.

## Подключение

В настройках сервера Core:

```text
PRICHAL_AI_URL=https://адрес-причал-ai
CORE_DIRECTORY_API_KEY=отдельный-ключ-не-короче-32-символов
```

Укажите базовый HTTPS-адрес, без `/api/v1/core/directories`. Если `PRICHAL_AI_URL` не задан, используется существующий `AI_AGENT_URL`. Ключ должен совпадать с `CORE_DIRECTORY_API_KEY` на сервере AI. Не используйте ключ Saby или Telegram. Перезапустите приложения после изменения переменных. API справочников должен быть развёрнут на AI (по предоставленному контракту он включён в v0.3.12).

Core обращается к `/api/v1/core/directories` с сервера, передавая ключ в Authorization. Браузер ключ не получает. HTTPS проверяется, редиректы не выполняются. Запрос ограничен сетевыми таймаутами и 5 МиБ ответа. Во время сетевого запроса соединение PostgreSQL не удерживается.

## Как пользоваться

1. Открыть **Админ → Связь с Saby**.
2. Нажать **Загрузить из Причал AI**. Это ручная загрузка; автоматический опрос AI в фоне не добавлен.
3. Во вкладке «Магазины» выбрать существующую карточку Core для каждой точки и подтвердить связь.
4. Во вкладке «Учётки» выбрать сотрудника Core и подтвердить. Точное совпадение нормализованного имени показывается как подсказка, но ничего не выбирается автоматически. Сокращённые ФИО сопоставляются вручную.
5. Общую кассовую учётку отметить как общую, без связи с конкретным сотрудником. Ночные помощники и другие сотрудники без Saby могут оставаться без связи.

Есть поиск по имени, названию и ID, фильтры связей и отсутствующих записей, список карточек Core без связи. Отображаются варианты имени, магазины и даты наблюдений, время получения снимка в Core и время последней успешной загрузки в AI.

Это учётки, наблюдавшиеся в продажах, не кадровый справочник. Даты не означают приём/увольнение, магазины не означают кадровое закрепление. Связь не доказывает фактического автора каждого чека.

## Данные и ограничения

- Проверяются версия схемы, полнота снимка, типы и уникальность строковых ID, счётчики, ссылки на магазины, исключение РЦ 23109.
- Валидный снимок заменяется целиком в транзакции. При ошибке предыдущий снимок сохраняется, ошибка и время попытки видны в интерфейсе. Одновременная повторная загрузка отклоняется; зависшая попытка допускает повтор через две минуты.
- Исчезновение записи, в том числе пустая выгрузка, не удаляет подтверждённую связь. Она помечается «Нет в последней выгрузке». Можно снять связь; привязать отсутствующую запись заново нельзя до её появления.
- Один магазин Core связывается с одной точкой Saby. Несколько разных учёток Saby могут принадлежать одному сотруднику Core. Одна учётка связывается максимум с одним сотрудником либо помечается общей.
- Изменения связей и успешные загрузки записываются в общий журнал администратора. Конфликт изменения одной связи двумя администраторами возвращает предложение обновить список.
- При смене адреса источника после первой успешной загрузки импорт блокируется во избежание смешения справочников. Для переезда AI сначала требуется отдельно согласовать сохранение идентичности источника; автоматического сброса связей нет.
- Связи хранятся только в Core. Обратной отправки core_employee_id в AI, статистики, графика и расчёта зарплаты этот выпуск не добавляет. Существующие магазины/сотрудники Core не создаются и не переименовываются автоматически.

## Установка и проверка

Перед обновлением сохраните резервную копию БД. Новые таблицы снимка и связей создаются автоматически версионированной миграцией. Прежние переменные PostgreSQL/S3 сохраняются. В архиве Dockerfile и main.py находятся в корне.

Прошли 42 Python-теста (21 новый для справочников и 21 прежний), 19 Node/DOM-тестов, отдельный DOM-сценарий загрузки фото и проверка синтаксиса. Покрыты доступ, строковые BIGINT ID, некорректные снимки, пустая выгрузка, сохранение связей и снимка при ошибке, общие учётки, конфликты, уникальность магазинов, HTTP-заголовок авторизации, блокировка редиректов, создание новых таблиц поверх существующей схемы и повторный запуск.

Python-тесты используют изолированную SQLite, HTTP — тестовые ответы. Рабочие PostgreSQL, Причал AI, S3 и Telegram WebView здесь не использовались. Сборка на сервер не развёрнута. После установки выполните одну загрузку в админке и подтвердите первые связи.

Команды тестов: `pytest -q tests/test_directories.py tests/test_upgrade.py`; для интерфейса `npm install --prefix tests`, затем `npm test --prefix tests`.
