# Причал Core v1.7.10 — Security & Permissions Stabilization

## Что изменено

v1.7.10 не добавляет новые бизнес-функции. Версия переводит рабочие API Core на единую матрицу ролей, созданную в Админ-центре.

### Источник прав

Авторитетным идентификатором доступа является `users.role_key`.
Поле `users.role` сохраняется только как совместимость со старым кодом и не должно предоставлять дополнительные полномочия.

Системный `admin` остаётся неизменяемым superuser. Пользовательская роль, даже если она скопирована с администратора, не становится системным администратором.

### Модель разрешений

Каждое действие проверяет:

- `access_level`: `hidden / view / edit`;
- `data_scope`: `own / stores / network`.

Проверки выполняются на backend. Скрытие кнопок MiniApp является только UX и не считается защитой.

### Модули

Матрица применяется к рабочим API:

- Заявки и справочники;
- График и подмены;
- Пересменки;
- Задачи;
- Проверки;
- Сотрудники;
- База знаний;
- Тестирование;
- Telegram;
- Главная/виджеты.

Фото и вложения также проверяют доступ к связанному объекту.

### Отключённые модули

Инкассация, Наставничество, План/факт, старый Рейтинг и старые Рассылки защищены серверным `module_guard`. Пока модуль отключён в `module_states`, прямой вызов его API возвращает HTTP 404.

### Проверка

В `scripts/security_smoke_test.py` есть изолированный SQLite regression test, который проверяет:

1. пользовательская роль не наследует права от старого `base_role`;
2. `stores` scope не выдаёт данные чужой точки;
3. прямой API-вызов запрещён при скрытом разрешении;
4. отключённый модуль нельзя открыть прямым URL;
5. системный администратор сохраняет полный доступ;
6. пользовательская роль с legacy `base_role=admin` не проходит admin-only API;
7. копирование роли Администратора не создаёт второго системного администратора.
